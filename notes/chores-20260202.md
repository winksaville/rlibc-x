# Chores Discussion - 20260202

## Decision: Extract xt to Standalone Project "tspec"

### Rationale

xt has nothing directly to do with rlibc-x - it's a general-purpose tool for managing "translation specs" that make it easier to effectively use various build tools and manage their options. It should be its own project.

### Name Selection

Evaluated options:

| Name | Status | Notes |
|------|--------|-------|
| **tspec** | ✅ Selected | Describes core concept, available on crates.io |
| **xt** | ❌ Taken | crates.io: "Translate between serialized data formats", active |
| **mts** | Available | "make ts" - but .mts is TypeScript ES module extension |
| **tspc** | Available | Vowel-dropped "tspec" - shorter but less readable |
| **cargo-tspec** | Not checked | Cargo plugin convention, longer |

**Decision: tspec**

- Directly describes what it manages (translation specs)
- Available on crates.io
- Users can alias/symlink to preferred name (t, ts, xt, etc.)

### What tspec Is

A declarative layer over cargo's complex flag combinations:
- tspec files (`.ts.toml`) capture reproducible build configurations
- Translates high-level options to tool-specific flags (rustflags, build-std, targets, linker scripts)
- Manages specs as first-class artifacts (`ts list`, `ts show`, `ts set`, `ts new`)

### Extraction Plan

1. Create new repo at `../tspec`
2. Move xt source code, adapt naming (xt → tspec)
3. Fix standalone package support (POP) - currently fails on non-workspace packages
4. Set up Cargo.toml metadata for crates.io publishing
5. Update rlibc-x to use tspec as external tool (or keep local copy initially)

### File Extension Question

Currently: `tspec.ts.toml`, `tspec-opt.ts.toml`

Options after rename:
- Keep `.ts.toml` - established, works
- Change to `.tspec.toml` - matches tool name
- Change to `.tspec` - shorter but loses .toml hint

Defer decision to tspec repo.
